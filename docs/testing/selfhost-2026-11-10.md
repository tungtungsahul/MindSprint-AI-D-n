# Nghiệm thu self-host SQL Server — 10/11/2026

## Phạm vi và trạng thái

Frontend và ASP.NET Core chạy trong `mindsprint-demo-web-1`, database là SQL Server
Express 2022 trong `mindsprint-demo-db-1`. Chỉ mở `127.0.0.1:8080`, giữ volume
`mindsprint-demo_sqlserver-data`. Tên Compose được giữ để tiếp tục dùng dữ liệu cũ.
Ứng dụng chạy chế độ Production. Không triển khai PostgreSQL cho bộ server này.

Đã áp dụng cấu hình và để hai container chạy healthy sau kiểm tra.

## Thay đổi

- `/healthz` kiểm tra tiến trình; `/readyz` thực hiện `SELECT 1`, trả 200/503.
- Probe SQL Server có timeout kết nối 2 giây, không retry kết nối; middleware timeout 3 giây.
- Web có Docker health check; cả hai service dùng `restart: unless-stopped`.
- Start chờ container healthy bằng Compose `--wait`; thêm lệnh Status.
- `scripts/selfhost-db.ps1` hỗ trợ Backup, VerifyRestore và Restore vào database mới.
- Backup có SQL checksum, COPY_ONLY và VERIFYONLY; xuất `.bak` ra Windows và trả SHA256.
- Restore dùng tên/files mới, chạy CHECKDB, không ghi đè database hiện hành.
- `DATABASE_NAME` cho phép chuyển web sang database khôi phục; giữ database gốc để quay lại.
- Backup được Git/Docker build loại trừ; đồng bộ hướng dẫn và kế hoạch local sang SQL Server.
- Vá EF Core/JWT trong dòng 8.0 lên 8.0.34; đồng bộ SQLite của các chương trình kiểm tra.
- Vá dependency provider PostgreSQL đã tồn tại lên 8.0.11 để loại cảnh báo dependency cũ;
  không thay provider SQL Server đang dùng. Không mở thêm phạm vi PostgreSQL.

Bài AuthIsolationChecks cũ còn yêu cầu PostgreSQL hardcode localhost:5432. Đã chạy
riêng 40/40 qua bằng PostgreSQL tạm với schema tạo bởi image ứng dụng; container thử
đã được dừng/xóa. Đây là kiểm tra tương thích mã cũ ngoài phạm vi SQL Server,
không phải thành phần được thêm vào bộ self-host.

Lần thử health check đầu bằng `Database.CanConnectAsync` có trường hợp chờ SQL quá lâu;
đã thay bằng kết nối/probe trực tiếp có giới hạn timeout và chạy lại phép thử mất DB thành công.
Phép thử restart dùng SIGTERM mà .NET xử lý được; không nhận kết quả từ SIGKILL gửi
bên trong PID namespace vì tín hiệu đó không kết thúc PID 1 trong tình huống này.

Log kiểm tra nằm trong thư mục `output/` trên máy; không chứa thông tin đăng nhập được in từ test.

## Giới hạn nghiệm thu

- Đăng nhập Google bằng tài khoản thật và màn hình consent chưa được thực hiện.
- Không reboot/sleep máy của người dùng; chủ máy kiểm chứng theo runbook.
- Cốc Cốc chưa được kiểm tra vì không có executable trên máy.
- `unless-stopped` cần Docker Engine đang chạy; unhealthy không tự restart container.
- Không cài Chromium vào image; giới hạn nhập URL cần JavaScript giữ như runbook.
- Không mở LAN/Internet, đổi tên Compose/volume, hoặc chuyển dữ liệu sang PostgreSQL.
